# Quickstart: exporting a Lean project to NDJSON

`lean4export-rs` reads a Lean module's `.olean` files (the module plus all
its transitive imports) and writes the same NDJSON export stream as
[lean4export](https://github.com/leanprover/lean4export) v3.1.0 to
**stdout**.

## 1. Build

```bash
cd rust
cargo build --release
# binary: rust/target/release/lean4export-rs
```

## 2. Build the Lean project

The project must be built with `lake build` so that `.olean` files exist:

```bash
cd /path/to/your-lean-project
lake build
# produces .lake/build/lib/lean/<Module>.olean
```

The Lean toolchain must match the project's `lean-toolchain` file. The
exporter finds the toolchain's standard library (`Init`, `Lean`, `Std`,
`Batteries`, …) automatically via `LEAN_SYSROOT` (see step 4), so set it
to the toolchain the project uses, e.g.:

```bash
export LEAN_SYSROOT="$HOME/.elan/toolchains/leanprover--lean4---v4.30.0"
```

## 3. Export a module

From the project directory (`.lake/build/lib/lean` is on the default
search path):

```bash
lean4export-rs --export MyProject.MyModule > export.ndjson
```

- The module name is dotted, e.g. `Init`, `Test`, `Mathlib`.
- The export includes every constant of the module **and all its
  transitive imports** (one NDJSON object per line).
- The first line is the `meta` object (exporter/format/Lean versions).

### If the module is not on the default path

Add search directories explicitly (repeatable, searched in order):

```bash
lean4export-rs --export MyModule \
  --lean-path /path/to/project/.lake/build/lib/lean \
  --lean-path "$LEAN_SYSROOT/lib/lean" > export.ndjson
```

### Mathlib checkouts

For a Mathlib checkout, generate the `--lean-path` flags with the helper
script (main build dir first, then every `.lake/packages/*` build dir):

```bash
lean4export-rs --export Mathlib \
  $(bash rust/scripts/mathlib_roots.sh /path/to/mathlib4) > mathlib.ndjson
```

## 4. Options

| Option | Description |
|---|---|
| `--export-mdata` | Keep `mdata` expression nodes (default: stripped like `removeMData`) |
| `--export-unsafe` | Include unsafe declarations (default: skipped) |
| `--limit N` | Stop after N non-internal constants (debugging) |
| `--only <name>` | Dump only the named constant(s); repeatable, e.g. `--only MyModule.Even` |
| `--only-prefix <prefix>` | Dump every non-internal constant whose name starts with the prefix; repeatable, e.g. `--only-prefix Nat.` |
| `--lean-path <dir>` | Add an `.olean` search directory; repeatable |

Environment:

- `LEAN_SYSROOT` — path to the toolchain root (must contain `lib/lean`).
  Defaults to the `lean` prefix on `PATH` if unset.

Examples:

```bash
# Per-constant export (with the mdata variant)
lean4export-rs --export Phase0Test \
  --only Phase0Test.withLet --export-mdata > withLet.mdata.ndjson

# Every Nat.* constant (the constant itself plus its dependencies)
lean4export-rs --export Init --only-prefix Nat. > nat.ndjson

# Full Mathlib export, unsafe declarations included
lean4export-rs --export Mathlib --export-unsafe \
  $(bash rust/scripts/mathlib_roots.sh /path/to/mathlib4) > mathlib.ndjson
```

`--only` / `--only-prefix` selections are unioned and can be combined
(`--only A --only-prefix B.`). Dependencies of the selected constants are
always included, so the output can be piped straight into nanoda for
verification.

## 5. Verify the output

The export is type-checked with zero errors by
[nanoda](https://github.com/ammkrn/nanoda_lib), an independent external
kernel checker. See [`nanoda-verification.md`](nanoda-verification.md)
for the config and results, or stream directly:

```bash
lean4export-rs --export Init --lean-path "$LEAN_SYSROOT/lib/lean" \
  | nanoda_bin nanoda-config.json
```

## Notes

- **Memory**: a full `Mathlib` export peaks at ~8 GB RSS; `Init`/`Lean`/
  `Test` at ~1.2–2.4 GB. The environment (all transitively imported
  constants) is loaded into memory before exporting.
- **Output size**: `Init` ≈ 6.4M lines / 340 MB, `Lean` ≈ 12.8M lines /
  724 MB, full `Mathlib` ≈ 104M lines / 5.9 GB.
- **Determinism**: the stream is deterministic for a given set of
  `.olean` files (constants iterate in `Name` order, expressions are
  deduplicated via content interning).
- The local Lean exporter's bvar behavior differs from this Rust
  implementation (see `bvar_dedup_fix.md`); golden files in
  `golden/phase0/` are regression references generated by this
  implementation, with correctness enforced by nanoda.
