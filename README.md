A simple declaration exporter for Lean 4 using the [Lean 4 NDJSON export format](./format_ndjson.md)

## How to Run

1. Build lean4export with `lake build`

2. Call the `lean4export` binary with the correct lake env set up.

```sh
lake env <path to lean4export binary> <lean file without .lean suffix>+
```

For example, let's assume we're working in the `mathlib4` directory, with the following structure: 
```
|__ mathlib4 (*we are here)
|__ lean4export
```

We can invoke the exporter on the "top level" mathlib file and export mathlib with the following command:
```sh
lake env ../.lake/build/bin/lean4export Mathlib > out.ndjson
```
This exports the contents of the given Lean module (here just the top level `Mathlib` module in the `Mathlib.lean` file), and its transitive dependencies. A specific list of declarations to be exported from these modules can be given after a separating `--`, and more than one module can be passed to the initial invocation by including more than one name (separted with a space).

### Options

The option `--export-unsafe` can be used to include unsafe declarations in the export file. This may be useful for testing and debugging other tools, where unsafe declarations can serve as negative examples.

The option `--export-mdata"` can be used to include `Expr.mdata` items in the export file, which are removed by default as they should not have an effect on type checking.

## Rust reimplementation (`rust/`)

`rust/` contains an independent Rust reimplementation (`lean4export-rs`) that
reads `.olean` files directly and emits the same NDJSON format, without going
through the Lean kernel. It reproduces the reference exporter's output
**byte-for-byte** on the `Init`, `Lean` and `Test` modules.

### Building and running

```sh
cd rust
cargo build --release
./target/release/lean4export-rs --export Init > Init.ndjson
```

The default search path is `./.lake/build/lib/lean` plus the toolchain's
`lib/lean` (found via `lean --print-prefix`); use `--lean-path <dir>` to add
more roots. `--export-mdata` and `--export-unsafe` mirror the Lean options.

### Architecture

- **`olean` crate** (`crates/olean/`) — `.olean` reader.
  - `region` / `object` / `header`: parse the compacted-region format
    (see [`OLEAN_FORMAT.md`](./OLEAN_FORMAT.md)).
  - `decode`: walk the object graph into `value::ModuleData`.
  - `value`: the decoded data model (see below).
  - `export`: render `ModuleData` as NDJSON, mirroring `Export.lean`'s
    `dumpName`/`dumpLevel`/`dumpExprAux` with the same memoization and
    dedup (alpha-equivalence) behavior.
- **`lean4export-rs` binary** (`src/main.rs`) — CLI front end.

### Arena design

`Name`, `Level` and `Expr` are **`Copy` `u32` handles** into flat node
arenas, not heap-allocated trees:

- Each node is a `#[repr(u8)]` tagged enum of 8–24 bytes stored contiguously
  (`ExprTable`/`NameTable`/`LevelTable`), instead of a 40-byte `Expr` plus a
  16-byte `Rc` control block per node (~56 bytes).
- Nodes are **content-interned at decode time**, so structurally equal
  subterms share one index; index equality *is* structural equality
  (O(1) comparisons, shared memoization caches during export).
- Decode-time interning maps are dropped after the environment is loaded
  (`ExprTable::drop_intern_maps`), before export starts.
- The exporter's caches are keyed by `u32` node index, and its
  `removeMData`-stripped scratch nodes are appended after the env range
  and never reused (handles to them live in long-lived maps).

This cuts the environment's expression memory ~4x per node and, combined
with memoization, makes full exports of `Lean`/`Test` (15.4M NDJSON lines)
run in ~1 minute at ~2.4GB peak RSS.

### Verification

All three modules are exported byte-identical to the golden references in
`golden/phase0/` (generated by the reference Lean exporter):

| Module | Lines | Time | Peak RSS |
|---|---|---|---|
| Init | 7,471,899 | ~18 s | ~1.2 GB |
| Lean | 15,463,154 | ~53 s | ~2.4 GB |
| Test | 15,474,364 | ~51 s | ~2.4 GB |

`cargo test` covers the arena tables (interning, scratch, name formatting,
`DataValue` repr) and `cargo clippy --workspace --all-targets` is clean.

`Phase0Test.lean` declares constants of every kind the export format
supports; its `.olean` is the cross-check input for the Rust reader
(`golden/phase0/const/*.ndjson` are the per-constant golden outputs).
